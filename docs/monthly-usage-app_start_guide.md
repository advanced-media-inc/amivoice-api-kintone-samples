# AmiVoice 使用量CSV表示アプリ（AmiCostViewerES） スタートガイド

## 1. 概要

本アプリケーションは、AmiVoice API の使用量 CSV を動的に取得し、kintoneのテーブルに使用量（ミリ秒）と料金（円）を表示します。

- `quantity_table`: 使用量の明細
- `cost_table`: エンジンプランごとの料金

**注意**: 本プラグインが使用する CSV 取得エンドポイント（`https://acp.amivoice.com/util/api/downloadusage/...`）は、AmiVoice API の公開ドキュメント（[docs.amivoice.com](https://docs.amivoice.com/)）には記載されていません。予告なく仕様が変更される可能性がある点に留意してください。

## 2. 利用前の準備

### 2.1 必要なもの

- kintone 環境
- AmiVoice API の API キー
- AmiVoice API のサービス ID
- 取得対象年月（YYYYMM形式）
- AmiVoiceAPIアクセス用プラグイン-ami_cost_{Version}.zip（[リリースページ](https://github.com/advanced-media-inc/amivoice-api-kintone-samples/releases/latest)から取得）
- フォーム表示カスタムスクリプト-ami_maskkey.js

### 2.2 kintone アプリのフィールド設定

次のフィールドコードを、プラグインを利用するアプリに作成してください。フィールドコードは表示名ではなく、必ず次の値にします。

| 用途        | フィールド種別の例 | フィールドコード | 入力内容                       |
| ----------- | ------------------ | ---------------- | ------------------------------ |
| API キー    | 文字列（1行）      | `apikey`         | AmiVoice API の API キー       |
| サービス ID | 文字列（1行）      | `serviceid`      | AmiVoice API のサービス ID     |
| 対象年月    | 文字列（1行）      | `date`           | 取得対象年月（6桁の `YYYYMM`） |
| 使用量明細  | テーブル           | `quantity_table` | CSV の使用量行を保存           |
| 料金明細    | テーブル           | `cost_table`     | プラン別の料金を保存           |

#### `quantity_table` の列

使用量テーブルには、左から次の4列を作成してください。

| 順番 | 内容             | 推奨フィールドコードの例                      |
| ---- | ---------------- | --------------------------------------------- |
| 1    | 年月（YYYYMM）   | `yyyymm` または `year` / `month` を含むコード |
| 2    | アカウント名     | `account`                                     |
| 3    | エンジンプラン名 | `engine` または `plan`                        |
| 4    | 使用量（ms）     | `ms` または `msec`                            |

#### `cost_table` の列

料金テーブルには、左から次の2列を作成してください。

| 順番 | 内容             | 推奨フィールドコードの例 |
| ---- | ---------------- | ------------------------ |
| 1    | エンジンプラン名 | `engine` または `plan`   |
| 2    | 料金             | `cost` または `price`    |

列のフィールドコードに上記のキーワードを含めると、プラグインが列の用途を自動判定します。自動判定できない場合は、テーブル内の列の定義順に割り当てられます。そのため、キーワードを含めないフィールドコードを使う場合は、必ず表の順番どおりに列を配置してください。

料金と使用量の列は、文字列（1行）または数値フィールドを使用できます。API キーは、他の利用者が閲覧できる一覧画面に表示しない運用を推奨します。

## 3. プラグイン（ami_cost_{version}.zip）の導入

1. kintone のシステム管理を開きます。
2. プラグインの管理画面で、[リリースページ](https://github.com/advanced-media-inc/amivoice-api-kintone-samples/releases/latest)から取得した `ami_cost_{version}.zip` などのプラグイン ZIP ファイルをインストールします。
3. kintone のアプリ管理画面から対象アプリを開きます。
4. アプリの設定画面で「プラグイン」を開き、インストールしたプラグインをアプリに適用します。
5. アプリを更新して設定を反映します。

本プラグインには個別のプラグイン設定画面はありません。API キー、サービス ID、対象年月は各レコードのフィールドに入力します。

## 3.1 カスタムスクリプト（ami_maskkey.js）の導入

API キーをマスク表示するため、kintone アプリにカスタムスクリプトを追加します。

1. kintone の管理画面から対象アプリを開きます。
2. アプリの設定画面で「カスタマイズ」を開きます。
3. 「JavaScript および CSS によるカスタマイズ」セクションを確認します。
4. 「JavaScript ファイル」の「ファイルを追加」ボタンをクリックします。
5. `ami_maskkey.js` ファイルをアップロードします。
6. スコープを「デスクトップ」に設定します。
7. アプリを更新して設定を反映します。

このスクリプトにより、フォーム画面での API キー入力欄がマスク表示（パスワード形式）となり、セキュリティが向上します。

## 4. 料金明細の取得手順

1. 対象レコードを新規作成または編集します。
2. `apikey` に AmiVoice API の API キーを入力します。
3. `serviceid` にサービス ID を入力します。
4. `date` に対象年月を6桁で入力します。
   - 例: 2026年7月の場合は `202607`
   - `2026/07`、`2026-07`、`20267` は使用できません。
5. レコードを保存します。
6. プラグインが自動的に AmiVoice API から料金明細を取得し、テーブルを更新します。
7. 更新完了後、最新の料金明細がテーブルに反映されます（ページの再読み込みは行われません）。

処理完了後、`quantity_table` と `cost_table` に料金明細が自動的に保存されます。取得・保存が終わるまでレコード詳細画面の表示が待たされるため、表示された時点で料金明細は反映済みです（編集ロックは行われません）。

## 5. 表示されるデータ

AmiVoice API から取得した CSV の各行は、次のルールで処理されます。

### 5.1 使用量明細（`quantity_table`）

料金行ではない CSV 行を、次の4項目として保存します。

- YYYYMM
- アカウント名
- エンジンプラン名
- 使用量（ms）

CSV の「識別子」や「使用量（秒）」など、5列目以降の項目は保存されません。

### 5.2 料金明細（`cost_table`）

次の条件を満たす行を料金行として判定します。

- アカウント名が `01` で終わる
- 料金が空でない
- 使用量（ms）が空である

料金行は使用量テーブルには保存されません。エンジンプランごとに料金を合算し、次の2列で `cost_table` に保存します。

- エンジンプラン名
- 合算料金

無料枠などで料金行がないプランは、料金テーブルには表示されません。

## 6. API 接続仕様

プラグインは次の API に GET リクエストを送信します。

```text
https://acp.amivoice.com/util/api/downloadusage/{サービスID}/{YYYYMM}
```

サービス ID が `01` で終わらない場合は、URL 上ではサービス ID の前に `Ami.` が付加されます。

```text
https://acp.amivoice.com/util/api/downloadusage/Ami.{サービスID}/{YYYYMM}
```

認証には次の HTTP ヘッダーを使用します。

```text
Authorization: Bearer {APIキー}
```

## 7. API キーの取り扱いについて

API キーの漏えいを防ぐため、次の対策が実施されます。

**取得処理時:**
- 料金明細を取得した後、API キー（`apikey` フィールド）は自動的に削除されます。

**画面表示時:**
- フォーム画面ではAPI キーはマスク表示となります
- レコード画面ではAPI キーの表示は空となります

**再取得時の注意:**
- 同じレコードで再度料金明細を取得するには、API キーを再入力してレコードを保存する必要があります。

## 8. エラーが発生した場合

### 「apikey、serviceid、date（YYYYMM）が未入力のため、料金明細を取得できませんでした。」と表示される

次を確認してください。

- `apikey` が空でないこと
- `serviceid` が空でないこと
- `date` が半角数字6桁であること
- フィールドコードが正しいこと（表示名ではなくフィールドコード）

### 「料金明細の取得に失敗しました」と表示される

次を確認してください。

- API キーが有効であること
- サービス ID が正しいこと
- 対象年月に利用可能なデータがあること
- kintone から `https://acp.amivoice.com` へ接続できること
- AmiVoice API が HTTP エラーを返していないこと

### テーブルが更新されない、または想定と違う列に入る

- テーブルのフィールドコードが `quantity_table` または `cost_table` になっているか確認してください。
- `quantity_table` は4列、`cost_table` は2列あるか確認してください。
- 列のフィールドコードに `yyyymm`、`account`、`engine`、`plan`、`ms`、`cost` などの判定用キーワードが含まれているか確認してください。
- キーワードを使わない場合は、列の定義順が仕様の順番になっているか確認してください。

## 9. 運用上の注意

- レコードを保存すると、自動的に AmiVoice API から料金明細が取得され、`quantity_table` と `cost_table` に保存されます。
- 取得処理を実行すると、対象レコードの `quantity_table` と `cost_table` は取得結果で置き換えられます。既存のテーブル内容を残したまま追加する処理ではありません。
- 取得対象年月は `YYYYMM` 形式（6桁の数字）で指定してください。
- 同じレコードで再取得する場合は、API キーを再入力して保存してください。
- 料金明細取得後、API キーはレコードから自動的に削除されます。
- アプリとスペースの閲覧権限を適切に設定し、API キーの入力画面にアクセスできるユーザーを制限してください。
- CSV の形式が AmiVoice API の想定形式と異なる場合、正しく振り分けられない可能性があります。
